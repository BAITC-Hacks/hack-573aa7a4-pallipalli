# OpenAI integration validation

Validated 2026-09-23 against the existing whole-plan-search agent.

## Final implementation

- **36 automated tests passed** across `test_agent`, `test_planner`, `test_openai_analyst`, and `test_analyst_evidence`.
- Offline report generation succeeded without the SDK in the Python import path.
- Explicit OpenAI mode with no configured key fell back to the offline report with reason `missing_api_key`.
- A live request to the OpenAI Responses API completed using `gpt-4.1-mini-2025-04-14`, through OpenAI Python SDK 2.54.0.
- The final grounded live request used **11,881 input tokens and 404 output tokens** and returned five valid hypotheses. Its factual choices, candidate identity matches, and allowed pilot questions passed local validation.
- Freezing those suggestions succeeded. See `policies/openai-proposal-v1.json`; it is marked inactive and requires evaluation.
- `agent.py`, `planner.py`, and `submission.csv` remain byte-identical to the previously evaluated planner revision. The analyst therefore introduces no campaign-score change; its contribution is reporting and proposed future experiments.

## Development finding

An earlier free-text live response completed but mixed candidate references and suggested unavailable churn/conversion metrics. It was not adopted as the example or frozen proposal. The integration was changed to make the model select from factual statement enums generated by Python, with exact candidate-to-pilot matching and allowed experiment questions. This illustrates why schema shape alone is insufficient for grounding numerical analysis.

Two live development requests were made in total. The first used 15,528 input tokens and 838 output tokens; the second is listed above. Unit tests use a fake client and make no paid API calls.

## Limits

This verifies the API integration, failure handling, grounding checks, and continued deterministic campaign behavior. It does not show that the five proposed experiments increase net ARPU. They have not been activated. Pilot estimates still refer to a synthetic local population, and hidden judging effects may differ.

The API key was supplied transiently to the live-check process and was not written to project files. Future runs read credentials from the environment.
